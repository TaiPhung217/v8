dm...@chromium.org<dm...@chromium.org> #15Mar 16, 2026 04:39PM
We have a loop phi with a Smi phi backedge and we don't call SetUseRequiresSmi. This backedge phi then gets untagged and we don't preserve its Sminess (because it doesn't have uses_require_smi). This is very similar to Issue 489280531, except that here the backedge is not a loop phi but just a regular phi.

This should only be a medium-severity vuln: it can lead to leaking the address of a HeapObject (probably even just a HeapNumber) by calling UnsafeSmiUntag on a HeapObject/HeapNumber.

Fix incoming.

    https://crrev.com/c/7633545 tried to make sure that we call 
    SetUseRequiresSmi when the backedge of a Phi has Smi type, but it was 
    using the static type of the backedge rather than its KNA type. For 
    loop phis, it's more or less the same, but for non-loop phis, the 
    static type is typically Any, whereas the KNA type is populated as 
    soon as a CheckedSmiUntag is encountered (as is the case in the 
    repro).
